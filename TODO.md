Word-pair context (`data/ru-pairs.bin`, after v1.3.0, dev only): candidate weight 0.5 + тся/ться after a typical previous word → dev 89.67% / 20.57% / 0.047% (v1.3.0: 89.13% / 19.43% / 0.046%). Measured and rejected: other real-word errors (стаей/статей) by the previous word (≤ 32% right on dev), ете/ите (no cases on dev), context veto (no gain). **Findings / next:** (a) about half of the dev "false on clean" changes are typos the gold standard left unmarked (позовляет, возращается, следущее, тепрь…), which caps the measurable precision near 95% — an owner-reviewed adjudication of those cases is needed before 95% is a fair target; (b) `data/ru.txt` (internet frequency list) is inside the RU Bloom filter and contains common misspellings (зделать, обьяснить, расчитывать, оффис, кажеться), so they count as known words and are never corrected — split them out for typo correction (OpenCorpora check + classic error patterns), tune on dev; enable RU auto by default once test precision ≥ 95%.
